## 1. 前日までの準備

### 1-2. 負荷テスト（担当: れい）

400人ぶんの「QR発行 → 交換 → 使用」を一気に流して、二重発行・二重利用がないこと、応答が遅すぎないことを確かめる。

```bash
BASE_URL=https://（本番のURL） STAFF_PASSWORD=（パスワード） npm run load-test
```

- 最後に `✅ 二重発行・二重利用なし` と出れば合格。`❌` が出たら当日までに原因を調べる
- **必ず前日までに実行する。** テストのチケットも今日の発行数・使用数に入るため、当日に実行すると管理画面の数が狂う（数は日付ごとなので、翌日には影響しない）
- 1回の実行で Redis のコマンドを約8,000回使う（無料枠の目安は「6. コマンド数の見積もり」）
- 目安: 手元の PC で動かしたときは、400人ぶんが約9秒、どの API も95%が200ミリ秒以内だった。本番（Vercel + Upstash）ではネットワークのぶん遅くなるので、95%が1秒以内なら問題ない

### 1-3. タブレットの準備（両店1台ずつ）

| やること | 理由 | 確認 |

| 画面の自動ロック（スリープ）を「なし」にする | 画面が消えるとQRが読めない | ☐ |

## 2. 当日の流れ

### 開店前
1. 両店のタブレットで `/tablet/...` を開き、QRが出ていることを確認する
2. 自分のスマホで1回だけ読み込んで、チケットが出ることを確認する（このチケットは使わずに残しておくか、相手の店で試しに使う）
3. 管理画面で、発行数が1増えたことを確認する

### 販売中（QRを渡す側）
- 1食お買い上げごとに「このQRを読み込むと、〇〇ゼミで △△ がもらえます」と案内する
- 読み込まれるとタブレットに「発行しました ✓」が1秒出て、次のQRに変わる。**✓ が出るのを見てから次のお客さんに案内する**
- 誰も読み込まなくても、QRは80秒ごとに自動で入れ替わる（古いQRは使えなくなる）

### 販売中（チケットを受け取る側）
お客さんが「チケットを使いたい」と言ったら、次の順で確認する。

1. お客さんのスマホに **チケット（オレンジの点線の枠）** が出ていて、**「（この店）で使えます」** と書いてあるか
2. お客さんに **店員の前で**「使う」→ 確認ダイアログの「使う」を押してもらう
3. **「使用済み」の画面で、背景が動いている** ことを確認する
4. 特典（たこ焼き＋2個 / 唐揚げ＋1個）を渡す

**スクリーンショット対策:** 使用済みの画面を撮ったスクリーンショットでは、背景が止まっている。
最初から「使用済み」の画面を見せられた場合は、使用時刻を確認する。目の前で押したのでなければ（使用時刻が数分以上前なら）、すでに使ったチケット。

### 閉店時
1. 管理画面で両店を「受付を停止する」にする（新しいQRが出なくなる。相手の店で使えるチケットも使えなくなる）
2. 管理画面の発行数・使用数を記録する（スクリーンショットでよい）
3. 停止は日付が変わると自動で解除される。翌日もそのまま使える

## 3. 受付停止の使いどころ

| 状況 | 操作 |
|---|---|
| 片方の店が売り切れた | 売り切れた店を「停止」。その店のタブレットからQRが消え、その店で使うチケットも「受付停止中」と表示される |
| 片方の店が一時的に休憩する | 休憩する店を「停止」→ 戻ったら「再開」。再開するとタブレットに自動でQRが戻る |
| トラブルで一度止めたい | 両店を「停止」 |

---

## 4. トラブル対応

| 症状 | 原因と対応 |
|---|---|
| タブレットに「通信できません。再接続しています…」 | ネットが切れている。Wi-Fi / テザリングを確認する。つながれば5秒以内に自動で戻る |
| タブレットに「パスワードが違います」 | パスワードを入れ直す。Vercel の `STAFF_PASSWORD` を変えた場合は、全タブレットと管理画面で入れ直しが必要 |
| タブレットに「ただいま受付を停止しています」 | 管理画面で停止されている。再開すれば5秒以内にQRが戻る |
| お客さんに「このQRは使用済みです」 | 先に別の人が読み込んだ。タブレットの次のQRを読み込んでもらう |
| お客さんに「QRの有効期限が切れています」 | 古いQRを読み込んだ（撮った写真のQRなど）。タブレットの今のQRを読み込んでもらう |
| お客さんに「ただいま受付を停止しています」 | 使う店が停止中。管理画面を確認する |
| お客さんに「通信できませんでした」 | お客さんのスマホの電波が悪い。ページを再読み込みしてもらう。受け取り済みのチケットは消えない |
| お客さんがチケットの画面を閉じてしまった | 同じQRのページ（ブラウザの履歴）を開き直すと、自分のチケットに戻れる。履歴もない場合は、店の判断で新しいQRを読み込んでもらう |
| 全員がエラーになる | Vercel のダッシュボードでエラーを確認する。Upstash の無料枠を使い切っていないかも確認する |
